# Todo App: Project Structure

**Stack:** SvelteKit (Svelte 5, runes) · Tailwind CSS v4 · shadcn-svelte (desktop UI) · Framework7 (phone/tablet UI) · `@lucide/svelte` icons · pnpm.
**State:** frontend only. Data comes from seeded in-memory mock data; the backend contract is typed and ready to swap in. No auth yet.

## Two UIs, one core

```
                 routes/(app)/+layout.svelte
                 detectUiMode()  (shared/application/device.ts)
                  /                               \
       desktop   /                                 \  phone / tablet  (lazy import)
                ↓                                   ↓
   header + <main>{@render children()}</main>   mobile/MobileApp.svelte  (Framework7 <App>, UI only)
                \                               /   + <div class="view view-main">
                 \                             /
            routes/(app)/todos/**/+page.svelte   ← same SvelteKit routes, URLs and history for both UIs
                 detectUiMode() branch per route
                 /                             \
    desktop     /                               \   mobile (dynamic import)
               ↓                                 ↓
   modules/*/presentation/pages         mobile/modules/*/presentation/pages
   modules/*/presentation/components    mobile/modules/*/presentation/components
   shared/presentation/ui/*.base        mobile/ui/*.base.svelte
   shared/presentation/ui/shadcn-ui/*   framework7-svelte / F7 CSS classes
                \                             /
                 ↘                           ↙
              modules/*/domain   (types, validator, form, bindings, controllers)
                               ↓
                      modules/*/data/api.ts
                               ↓
              network/features/*.ts → mock (network/mock)  or  transport/http.ts
```

Rules:
- Only `shared/presentation/ui/*.base.svelte` imports shadcn-ui.
- Only the mobile layer (`mobile/ui/*.base.svelte`, `mobile/MobileApp.svelte`, and `mobile/**` pages/components such as `DataTable`) touches Framework7 (the `framework7-svelte` package or its CSS classes). Desktop code never imports it.
- `domain/`, `data/` and `network/` never import any UI library, so both UIs share them.
- Route files call `detectUiMode()` and branch: desktop skeleton (static import) or mobile page (dynamic import, so `framework7-svelte` never enters the desktop bundle). No other logic.

## UI selection (`shared/application/device.ts`)

Phones and tablets get Framework7; everything else gets shadcn.
- Decided once at startup, not on resize, so page state is never destroyed mid-session.
- Signals: primary pointer is touch with no hover, a mobile user agent, or iPadOS (reports as a Mac with touch points).
- **Screen width is not used.** A narrow desktop window stays on the desktop UI. DevTools device mode switches to mobile after a reload.
- Test override: `?ui=mobile` or `?ui=desktop` in the URL (remembered for the session via `sessionStorage`), or `VITE_FORCE_UI`.
- Framework7's JS and CSS are loaded with a dynamic import, so desktop users never download them.

## Framework7 integration notes

These rules came from real bugs; keep them unless you re-test.

**Framework7 is UI only — SvelteKit owns routing**
- F7's router is **not used**: no `<View>` component, no F7 `routes`, no F7 history (`browserHistory` is gone with the router). URLs, navigation and back are plain SvelteKit (`goto()`, `history.back()`, links), so the browser/system back gesture and the in-app Back control always pop the same history entry — the back button can never exit the app after a chain of navigations (the bug that removed the old "guard" bridge).
- `clicks: { externalLinks: 'a' }` in `mobile/f7.ts` is mandatory: F7's document-wide click handler then treats every `<a>` as external and returns **before** `preventDefault`, so SvelteKit's link handling (which bails when `event.defaultPrevented`) runs untouched. `ListItem link="…"` links therefore navigate exactly once, via SvelteKit.
- `mobile/routes.ts`, `navigation.ts` and `browser-back.svelte.ts` (the `pushState` guard + `blockSvelteKitLinkNavigation`) were deleted with the F7 router. Do not reintroduce a second history manager: the browser's own back/edge-swipe/system-back pops SvelteKit history directly.
- Page lifecycle events (`onPageAfterIn`, `pageInit`, …) never fire without the F7 router, so `onshow` was removed. Pages refetch in `onMount`: SvelteKit remounts the page component on every navigation to its route, including back navigation.
- Params come from `$app/state` (`page.params.id`), same as the desktop skeletons.

**Page transitions (`MobileApp.svelte` + `router_clone/presentation/page-transitions.css`)**
- F7's router used to animate push/pop; that is reimplemented with the **View Transitions API**: `onNavigate` in `MobileApp.svelte` (mobile-only mount point) calls `document.startViewTransition`, sets `data-vt="forward|backward"` on `<html>` from route-depth comparison, and resolves its promise inside the transition callback (SvelteKit's documented pattern) while awaiting `navigation.complete`.
- `page-transitions.css` reuses F7's own keyframes (`ios-page-*`, `md-page-*`, `--f7-page-transition-duration`) on `::view-transition-old/new(root)`, scoped by `html.ios` / `html.md` + `[data-vt]`. `data-vt` is removed when the transition finishes.
- Skipped entirely when `document.startViewTransition` is missing or `prefers-reduced-motion: reduce` is set (instant swap, same as no transition). Desktop never registers the hook.

**Edge-swipe back (`mobile/router_clone/application/edge-swipe-back.ts`)**
- Revived as a plain touch gesture (no router): a quick left-edge swipe right on any page with `back` calls the shared `router_clone/application/back.ts` `goBack()` (`history.back()`, deep-link fallback `goto('/todos')`). Wired in `page.base.svelte`'s `onMount` only when `back` is set; cleanup on unmount. It is **non-interactive** (the page does not follow the finger) — that keeps it compatible with PTR and swipeout, and one gesture can never go back twice.
- All in-app "go back" call sites use `router_clone/application/back.ts` — never `goto()` for back, which would push a new entry.

**Pages (`mobile/ui/page.base.svelte`)**
- Keep the navbar `title` **static**; changing it after mount is a known F7 quirk (navbar sizing).
- Back is a custom `navLeft` snippet: the same DOM F7's `backLink` renders (`a.link.back.icon-only` + `i.icon-back`), but with its own `onclick` = `preventDefault()` + `history.back()` (or `goto('/todos')` when the app was deep-linked as the very first history entry, so Back never leaves the app). F7's `backLink` prop cannot be intercepted (the event is dropped before it reaches us) and renders `href="#"`; `backLinkUrl`/`backLinkForce` push a new page — never use them.
- Pull-to-refresh: F7 creates PTR instances in its router's `pageInit` hook, which never runs. `page.base.svelte` calls `f7.ptr.create(el)` manually in `f7ready` — scoped to its own page via a `data-ptr-host` attribute so a still-mounted outgoing page can never be picked up — and `f7.ptr.destroy(el)` in `onDestroy`, the same lifecycle F7 uses in `pageBeforeRemove`.
- The navbar must stay a direct child of `.page` for the `--f7-page-navbar-offset` CSS: `framework7-svelte`'s `<Page>` moves `[data-f7-slot="fixed"]` children (the `<Navbar>`) out of `.page-content` itself, with or without the router.

**Route files and the layout**
- `(app)/+layout.svelte` always renders `children` (wrapped in the lazy `MobileApp` on mobile), so routing is identical for both UIs; desktop never downloads Framework7.
- Each `(app)/**/+page.svelte` branches on `detectUiMode()`: desktop skeleton via static import, mobile page via `{#await import(...)}` (keeps `framework7-svelte` out of the desktop bundle). Mobile pages render only once `MobileApp` has loaded.

**Save/create must not push a history entry (`EditPage.mobile`, `NewPage.mobile`)**
- Edit save → `history.back()` (pops the form entry; the detail remounts and refetches the saved data). Only when there is nothing in-app to pop (deep link as the first history entry) → `goto(detail, { replaceState: true })`.
- Create → `goto(detail, { replaceState: true })`: the form entry is replaced by the detail entry, so the stack stays `list → detail`.
- A plain `goto()` after saving pushed a second entry: Back from the detail returned to the stale form, then detail, then list — the exact bug these two flows exist to avoid. This is also why `history.back()` (not `goto`) is the in-app "go back" everywhere.

**Components whose callbacks did not fire**
- `fab.base.svelte` is built from F7's CSS classes (`fab fab-right-bottom`) with a native click handler. The `<Fab>` component's `onClick` did not fire and its `fixed` slot did not render.
- `field.base.svelte` uses native `<input>`, `<textarea>` and `<select>` with `bind:value` inside F7 list-input classes, because `<ListInput>`'s `onInput` was not reliable. It manually toggles F7's focus classes (`item-input-focused` / `input-focused` on focus/blur) — normally added by F7's Input module, which never sees our native inputs — and renders F7's `.input-clear-button` (shown via the `item-input-with-value` class) when `clearable` is set (Title field).
- `button.base.svelte` is a native `<button>` with F7's button CSS.
- `list-item.base.svelte` still uses F7's `ListItem`, `SwipeoutActions` and `SwipeoutButton` (checkbox toggle and swipe-to-delete; the delete confirm runs through F7's Dialog, which **is** in the lite bundle). If either stops working, convert it the same way.

**List page UX (`ListPage.mobile.svelte`)**
- F7 `.segmented segment-colored` filter buttons (All/Active/Done) bound to the shared controller's `filter` state (same filter values as the desktop skeleton).
- Loading state uses F7 skeleton rows (`.skeleton-text` + `.skeleton-effect-wave`) instead of plain "Loading…" text; Edit/Detail pages use the same pattern.
- Swipe-delete and Detail delete both show `f7.toast` ("Todo deleted"); Detail delete confirms via `f7.dialog.confirm` and pops back with `router_clone/application/back.ts`.
- Empty filtered list shows a hint instead of a blank page.

**Form safety**
- `Form.mobile.svelte` (formerly `TodoForm.mobile.svelte`) owns ALL mobile form UI: field list, submit button with `busy` label, validation errors, and the save-failure banner — the pages pass `error`/`busy` down instead of rendering their own red message. It seeds its state once from `initial` using `untrack`.
- New and Edit pages catch errors and pass them to `Form`. The mock falls back to a generated id when `crypto.randomUUID()` is unavailable (insecure origins such as `http://192.168.x.x`).

## Connecting a real backend

1. Set `VITE_USE_MOCK=false` and `VITE_BASE_URL` in `.env`.
2. The server must satisfy `TodosApi` in `network/types.ts`: `GET` and `POST /todos`, `GET`, `PATCH` and `DELETE /todos/:id`.
3. Add auth headers in `network/transport/http.ts` (`defaultHeaders`).

## Adding a new module

1. Copy `modules/todos` to `modules/<name>` and rename the types, controller and pages.
2. Add `network/features/<name>.ts` and export it from `network/index.ts`.
3. Add routes under `routes/(app)/<name>/` that branch on `detectUiMode()`: the desktop skeleton (static import) and the mobile page (`{#await import(...)}`).
4. For mobile, copy `mobile/modules/todos` and point the route's dynamic import at its pages.

## Known gaps

- Mock data resets on reload; there is no auth, no pagination and no other modules yet.
- Mobile pages load per route via dynamic import, so the first visit to a route has a brief (already-cached after app load) async gap while its chunk arrives.
